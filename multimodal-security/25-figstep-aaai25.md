# FigStep: Jailbreaking Large Vision-Language Models via Typographic Visual Prompts

| 项目 | 内容 |
|---|---|
| 作者 | Yichen Gong, Delong Ran, Jinyuan Liu, Conglei Wang, Tianshuo Cong, Anyu Wang, Sisi Duan, Xiaoyun Wang（王小云）（清华大学、卡内基梅隆大学、中关村实验室、山东大学等） |
| 会议 | AAAI 2025（Oral） |
| 原文 | [arXiv:2311.05608](https://arxiv.org/abs/2311.05608)、[代码与 SafeBench 数据集](https://github.com/thuccslab/figstep) |

## 一句话总结

不需要梯度、不需要优化：把有害问题改写成“制作 XX 的步骤：1. 2. 3.”，**用图片排版出来**，再配一句“请把图中空着的列表补全”，就能让开源 VLM 的平均越狱成功率从 44.8% 升到 82.5%；改进版 FigStep-Pro 对 GPT-4V 的成功率达到 70%。

## 背景与问题

VLM 通常由一个已做过安全对齐的 LLM 加上视觉编码器和连接层组成。连接层的训练目标是让图像“语义上”对齐到 LLM 的嵌入空间，但没人保证图像中的有害内容也会触发 LLM 原有的拒绝行为。作者用最简单的方法检验：同样的有害文字，从文本通道换到图像通道，安全对齐还在不在？

## 方法

FigStep 分三步，完全黑盒：

1. **改写**：把有害问题改写成以 “Steps to”“List of”“Methods to” 开头的陈述句（人工或用 GPT-4 少样本改写）。
2. **排版**：把陈述句渲染成 760×760 的图片，下方加上空白的编号列表 “1. 2. 3.”。
3. **诱导**：配一条固定的良性文本提示，告诉模型图中列表是空的，请为每一项生成约 100 字的详细内容。

文本里没有任何有害词语，有害意图全在图片中。

**FigStep-Pro**：针对带 OCR 审核的商用模型，把有害关键词切成多张子图，每张图单独看都读不出完整的有害文字，再让模型把它们拼起来理解。

**SafeBench**：作者构建的评测集，含 10 个禁止主题（违法活动、仇恨言论、恶意软件、人身伤害、欺诈、色情、隐私侵犯，以及法律、金融、医疗三类专业建议）共 500 个有害问题，另有 50 题的 SafeBench-Tiny。

## 关键结果

**主实验**（SafeBench，人工判定，5 次尝试中任意一次成功即算成功，表 1）：

| 模型 | 直接提问 | FigStep |
|---|---|---|
| LLaVA-1.5（Vicuna-7B） | 57.4% | 84.0% |
| LLaVA-1.5（Vicuna-13B） | 45.4% | 88.2% |
| MiniGPT-4（Llama-2-Chat-7B） | 23.8% | 82.6% |
| MiniGPT-4（Vicuna-7B） | 50.6% | 68.0% |
| MiniGPT-4（Vicuna-13B） | 83.4% | 85.2% |
| CogVLM-Chat-v1.1 | 8.2% | 87.0% |
| **平均** | **44.8%** | **82.5%** |

**与其他越狱对比**（MiniGPT-4 Llama-2-Chat-7B，违法活动 / 仇恨言论 / 恶意软件三类，表 3）：GCG 为 0% / 10% / 10%，最好的纯文本基线 DeepInception 为 52% / 22% / 54%，FigStep 为 82% / 38% / 86%；基于对抗图像的方法（如 [23](23-visual-adversarial-jailbreak-aaai24.md) 的 VAE）为 30% / 6% / 10%。

**闭源模型**（表 7）：

| 方法 | GPT-4o | GPT-4V |
|---|---|---|
| 直接提问 | 28% | 18% |
| FigStep | 48% | 34% |
| FigStep-Pro | 62% | 70% |

**消融**（SafeBench-Tiny）：只给文字版的 FigStep 内容、只给图片、或把有害问题放进图片但不用“补全列表”的提示，成功率都明显下降；三者组合才达到最高（例如 LLaVA 上 92%）。

**为什么有效**：t-SNE 可视化显示，纯文本时有害和良性问题在最后一层嵌入中可以分开；换成排版图片后两者混在一起。作者的结论是：视觉嵌入只在**语义**上对齐到了 LLM，而没有在**安全**上对齐。

**防御测试**：
- OCR 检测：EasyOCR 能识别 88.98% 图片中的文字，但再用 LLaMA-2 或 OpenAI Moderation 判定有害的比例只有 40% 和 30%；把文字颜色调到几乎和背景一致的 FigStep-hide 仍有 52%–68% 的成功率。
- 系统提示中加入有害性检查：效果有限（LLaVA 不变，CogVLM 从 82% 降到 64%）。
- 加高斯噪声：几乎无效。

## 贡献与意义

1. **最朴素也最有效**：不需要任何优化，人人可用，成本极低；被集成进 NVIDIA 的开源 LLM 扫描工具 garak。
2. **指出跨模态安全对齐的缺口**：LLM 的安全对齐不会自动迁移到视觉通道，需要专门的跨模态安全对齐。
3. **公开了 SafeBench 基准**：500 个问题覆盖 10 类主题，连同代码一起开源，便于后续研究复用。
4. 和 [27 BoN](27-best-of-n-jailbreaking-neurips25.md) 中的排版图像增强一起，说明“把文字画成图”本身就是一条有效的越狱通道。

## 局限

- 成功率由人工判定，且 5 次尝试中一次成功即算成功；作者用 HarmBench 式的自动评判器复核时，数值明显更低（例如 92% / 90% / 82% 降到 72% / 72% / 64%）。
- 部分模型（如 CogVLM、MiniGPT-4 Vicuna-7B）本身理解能力有限，直接提问的低成功率不代表它们更安全。
- GPT-4V / GPT-4o 的结果是 2023 年底的快照，商用系统此后已更新。
- FigStep-Pro 需要多图输入，单图模型无法使用。

## 对研究者的启示

- 评测 VLM 安全时，至少要把文本攻击集“排版成图片”再测一遍，这是成本最低的跨模态一致性检查。
- 只靠 OCR 加文本审核不够：文字可以被拆分、隐藏或换成手写风格。
- 报告越狱成功率时应说明判定方式和尝试次数，人工判定与自动判定的差距可能达到 20 个百分点（另见 [18](../security-for-ai/18-chasing-shadows-llm-security-pitfalls.md) 对评估陷阱的总结）。

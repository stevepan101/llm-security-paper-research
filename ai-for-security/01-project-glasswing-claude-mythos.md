| 项目 | 内容 |
|---|---|
| 机构 | Anthropic（Frontier Red Team） |
| 时间 | 2026-04-07 |

| 原文 | [Claude Mythos Preview 技术报告](https://www.anthropic.com/research/mythos-preview)、[Infosecurity 报道](https://infosecurity-magazine.com/news/anthropic-launch-project-glasswing) |

## 一句话总结

一个通用前沿模型（并非专门为安全训练）在漏洞发现与利用上达到了可以在所有主流操作系统和浏览器中找到并利用 0-day 的水平。Anthropic 因此决定不公开发布这个模型，只通过 Project Glasswing 提供给关键软件的防御方使用。

## 背景与问题

此前的 LLM 漏洞挖掘工作（Big Sleep、AIxCC 等）证明了模型“能找到”真实漏洞，但离稳定写出可用 exploit 还有很大距离。这份报告回答的问题是：当模型的通用编程、推理和自主能力继续提升时，攻防能力会跃升到什么程度，防御方又该如何准备。

## 方法

- **环境**：每个测试在隔离容器中运行，容器内放置目标项目，由 Claude Code（Mythos Preview 驱动）配合简短的提示词去“找一个漏洞”。
- **并行分工**：先按“包含漏洞的可能性”给文件排序，再把不同文件分配给不同 agent，避免重复发现同一个漏洞。
- **过滤**：最后由一个 agent 审查所有报告，剔除影响很小或过于冷僻的问题。
- **聚焦内存安全漏洞**：sanitizer 可以可靠地确认这类漏洞，误报更少。
- **评估方式**：现有基准基本已被模型做满，所以主要用“真实 0-day 发现”来评估，这也排除了模型背题的可能。

## 关键结果

| 指标 | Opus 4.6 | Mythos Preview |
|---|---|---|
| Firefox JS 引擎基准：可用 shell exploit 数（数百次尝试） | 2 | 181（另有 29 个可控寄存器） |
| 约 1000 个 OSS-Fuzz 仓库：在已打全补丁的目标上实现完整控制流劫持 | 0 | 10 |

代表性发现：
- **OpenBSD**：一个 27 年的 TCP 漏洞，可远程使主机崩溃；约 1000 次运行，总成本不到 2 万美元。
- **FFmpeg**：一个 16 年的 H.264 漏洞，几百次运行，约 1 万美元；FFmpeg 8.1 修复了 3 个相关问题。
- **FreeBSD NFS**：一个 17 年的远程代码执行漏洞（CVE-2026-4747），在初始指令之后无需人工参与即完成利用。
- **Linux 内核**：多个漏洞串联实现提权；还有浏览器利用链、认证绕过等逻辑漏洞，以及密码学库的弱点。
- **严重性判断**：人工复核了 198 份报告，89% 与模型给出的严重性完全一致，98% 相差不超过一级。

## 贡献与意义

1. **能力跃迁的直接证据**：从“偶尔能写出 exploit”到“稳定批量写出 exploit”，生成 exploit 的成功数提升了约两个数量级。
2. **能力来自通用能力，而非专门训练**：说明安全能力会随前沿模型整体进步自然出现，难以靠“不训练安全数据”来规避。
3. **新的发布范式**：限制访问，只给防御方用，并为未公开漏洞提交 SHA-3 哈希承诺，等漏洞披露后再公开（最长 90+45 天）。
4. **给防御方的建议**：用现有前沿模型做漏洞发现、分诊和补丁；缩短补丁周期；改革漏洞披露流程以应对漏洞数量的暴增；为无人维护的遗留软件做好准备。

## 局限与疑问

- 超过 99% 的漏洞在报告发布时尚未修复，细节无法公开，外部难以完整复现。
- 评估集中在内存安全漏洞，对逻辑漏洞的覆盖相对较少。
- 限制访问能否真正防止滥用，业界有怀疑声音。

## 对研究者的启示

- 漏洞挖掘的研究重点会从“能不能找到”转向**验证、去重、分诊和修复的规模化**。
- “漏洞洪水”对披露流程和开源维护者负担的影响，是值得研究的新问题。
- 双重用途能力的发布治理（分级访问、承诺机制）本身就是 Security for AI 的研究方向。

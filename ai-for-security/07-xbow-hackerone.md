# XBOW：首个登顶 HackerOne 美国榜的自主 AI 渗透测试系统

| 项目 | 内容 |
|---|---|
| 机构 | XBOW（创业公司，创始团队来自 GitHub Copilot/Security Lab） |
| 时间 | 2025-06 |
| 类型 | 工业界成果（真实漏洞赏金平台） |
| 原文 | [XBOW：Top 1, how XBOW did it](https://xbow.com/blog/top-1-how-xbow-did-it/)、[CSO Online](https://www.csoonline.com/article/4012801/the-top-red-teamer-in-the-us-is-an-ai-bot.html) |

## 一句话总结

一个自主运行的 AI 渗透测试系统在真实的漏洞赏金平台上和人类白帽黑客同台竞争，并排到了美国榜第一。它的关键设计是用**验证器**（validator）消除 LLM 的误报。

## 方法

- **自主运行**：从攻击面探索到漏洞利用，全程不需要人工指导。
- **验证器**：充当“自动化同行评审”，确认每一个发现都真实存在：
  - 有的基于 LLM；
  - 有的是定制的程序化检查，例如用无头浏览器确认 XSS payload 确实被执行了。
- **人工参与之处**（为遵守 HackerOne 对自动化工具的政策）：
  - 提交前由 XBOW 安全团队审核；
  - 用 LLM 解析赏金项目的范围，再加一些人工整理。

## 关键数据

| 指标 | 数值 |
|---|---|
| 提交漏洞 | 约 1060 个 |
| 已解决 | 130 |
| 已分诊 | 303（多为 VDP 项目，确认问题但不一定修复） |
| 重复 / 仅供参考 / 不适用 | 208 / 209 / 36 |
| 近 90 天严重性分布 | 严重 54，高危 242，中危 524，低危 65 |

覆盖的漏洞类型：RCE、SQL 注入、XXE、路径遍历、SSRF、XSS、信息泄露、缓存投毒、密钥泄露等。还发现了 Palo Alto GlobalProtect VPN 的一个未知漏洞，影响 2000 多台主机。

## 贡献与意义

1. **真实世界的外部验证**：漏洞是否成立由赏金项目方而不是作者判定，这比自建基准可信得多。
2. **验证器设计**：用确定性检查（例如浏览器执行）来确认 LLM 的发现，是减少误报的有效工程模式。
3. 说明 Web 应用渗透测试这类“广度优先”的工作已经可以被 AI 大规模自动化。

## 局限与争议

- 排名部分来自**数量**优势：重复和仅供参考的报告合计超过 400 个，占比不低，会增加项目方的分诊负担。
- 并非完全无人参与，提交前有人工审核。
- 漏洞赏金的排名机制（声誉分）和“漏洞质量”并不完全等价。

## 对研究者的启示

- 验证器是让 LLM 安全工具实际可用的关键组件，“如何为不同漏洞类型自动构造验证器”值得研究。
- AI 大量提交报告对漏洞赏金生态（分诊成本、奖励机制）的影响是新的研究问题。

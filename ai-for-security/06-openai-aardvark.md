# Aardvark：OpenAI 的智能体安全研究员（现为 Codex Security）

| 项目 | 内容 |
|---|---|
| 机构 | OpenAI |
| 时间 | 2025-10-30 发布私测；2026-03-06 并入 Codex，以 Codex Security 名义推出研究预览 |
| 类型 | 工业界产品化研究 |
| 原文 | [Introducing Aardvark](https://openai.com/index/introducing-aardvark)、[The Hacker News 报道](https://thehackernews.com/2025/10/openai-unveils-aardvark-gpt-5-agent.html) |

## 一句话总结

基于 GPT-5 的安全 agent，它持续分析代码仓库，覆盖从威胁建模、漏洞发现、可利用性验证、严重性排序到补丁建议的完整流程。主要依靠 LLM 推理和工具使用，而不是模糊测试或软件成分分析。

## 工作流程

1. **威胁建模**：阅读整个仓库，理解项目的安全目标和设计，生成威胁模型；
2. **提交扫描**：监控新提交，结合威胁模型和整个仓库的上下文检查变更是否引入漏洞；
3. **验证**：在沙箱中尝试触发漏洞，确认可利用性，以减少误报；
4. **修复**：生成补丁（借助 Codex），供人工审查和一键应用。

## 关键数据

- 在包含已知漏洞和人为注入漏洞的“黄金”基准仓库中，召回了 **92%** 的漏洞。
- 在开源项目中负责任地披露了多个漏洞，其中 **10 个获得了 CVE 编号**。

## 贡献与意义

1. **把 AI 挖洞嵌入开发流程**：Big Sleep 和 Mythos 偏向离线研究，而 Aardvark 面向**持续集成**，每次提交都做安全审查，更接近“左移”。
2. **验证步骤**：通过沙箱验证可利用性来过滤误报，回应了 LLM 安全工具误报率高的老问题。
3. 产品化路线（并入 Codex）说明头部实验室认为 AI 代码安全审计已经接近可以实际使用。

## 局限

- 92% 的召回率是在自建基准上测的，没有公开精确率或误报率，也没有第三方复现。
- 公开信息中只有 10 个 CVE，和 Anthropic 报告的 500+ 相比，外部可验证的产出较少（也可能只是披露节奏不同）。
- 技术细节（scaffold、验证方式）公开得很少。

## 对研究者的启示

- “按提交增量审计”是一个很好的研究设定：上下文有限、变更明确，便于构造基准。
- 威胁模型生成本身值得单独评估：LLM 能否准确理解一个项目的安全边界？

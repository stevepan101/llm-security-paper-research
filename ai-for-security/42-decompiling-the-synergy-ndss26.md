## 一句话总结

这是第一项系统研究 LLM 如何与分析师协作做软件逆向工程（Software Reverse Engineering, SRE）的工作：先调查 153 名从业者，再让 48 名参与者（24 名新手、24 名专家）在两个 CTF 风格的二进制上做受控实验，发现 LLM 能缩小新手与专家的差距、加快已知算法函数的分诊，但也会带来有害的幻觉和无用的建议。

## 背景与问题

逆向工程需要从反编译输出里恢复程序语义，此前 LLM 在这个方向的工作多是自动化技术（例如本仓库的 [09 ReSym](09-resym-ccs24.md)，用 LLM 加程序分析恢复变量名和类型），评估对象是模型输出的准确率。但真实的逆向由人主导，LLM 在人的工作流里到底帮了什么、坏了什么，缺少系统证据。作者要回答：从业者现在怎么用 LLM 做逆向；LLM 对不同经验水平的人的理解程度、速度和产物质量有什么影响；它会在哪些地方误导人。

## 方法

### 1. 从业者调查（n = 153）
- 受访者构成：学生 43.1%，企业员工 27.5%，学术研究者 17.0%，自由职业者 9.2%；41.2% 有三年以上经验，40.5% 有一到三年。
- 工具：IDA Pro 81.0%，Ghidra 73.0%；所用 LLM 中 GPT 占 85.6%，Claude 占 11.6%。
- 喂给 LLM 的输入：反编译代码 59%，机器码 28%，中间语言 13%。
- 最常用的功能：函数总结 63.7%，函数识别 28.8%，函数重命名 23.3%，变量重命名 28.1%，漏洞识别 17.1%，库函数文档 2.1%。

### 2. 受控用户研究
- **参与者**：51 人完成，3 人因空白报告、无关内容或使用了动态分析被剔除，剩 **48 人**，分为 24 名新手和 24 名专家（专家身份为自评）。每人获 50 美元报酬。
- **任务**：每人做两道 CTF 风格的静态逆向题。**RPC**：自定义 RPC 协议，涉及 Base64、RLE、TEA 和以时间为种子的密钥；**Secrets**：加密文件管理器，密钥用 DJB2 哈希，含路径穿越漏洞。
- **实验设计**：每人在其中一题随机获得 LLM 辅助，另一题为对照组。
- **环境**：基于 BinSync 改造的 IDA Pro 9，通过 DOJO 平台的浏览器 VNC 提供；只允许静态分析，不能用调试器或运行程序。
- **LLM 工具**：研究团队开发的 DAILA 插件，提供上述六类功能和自由聊天。可选模型为 GPT-4o（默认）、GPT-4o-Mini、GPT-4-Turbo、Claude-3-5-Sonnet 和 Gemini-Pro。
- **评分**：参与者提交报告，按检查点（checkpoint）打分；两名评分者 85% 的评分完全一致，753/768 个得分点对齐（98%）。
- **数据规模**：共 109 小时的工作、96 份报告、1,517 次 LLM 交互。

## 关键结果

### 对理解程度的影响
- **新手受益明显**：新手的理解率（comprehension rate）从无 LLM 时的 0.04 升到 0.07，原文报告提升约 98%（p = 0.03，中等效应量；0.04、0.07 为四舍五入后的值），并且与专家之间不再有显著差异。
- **专家几乎没有变化**：LLM 对专家的理解率没有显著影响。作者据此概括为“LLM 缩小了专业能力差距”。

### 对产物（符号、注释、类型等）的影响
- 总产物数量上升：专家从 54 增至 84，新手从 41 增至 67。
- 但人工恢复的产物数与理解程度相关（p = 0.01），LLM 生成的产物与理解程度不相关（p = 0.34）。作者的解读是：给名字本身就是理解的过程，自动生成名字可能绕过了这一步。

### 对速度和准确度的影响
- 已知算法的函数（13 个）：LLM 重命名准确率 85%，人工 66%。其余 37 个函数：人工 65%，LLM 57%，差异不显著（p = 0.82）。
- 专家使用 LLM 分诊四个常见算法函数时，速度至少快 248%（摘要写作 2.4 倍）；但在两个自定义函数上至少慢 314%。

### 幻觉与误导
- 三次捏造的漏洞全部是 RPC 题中由 LLM 提出的缓冲区溢出。
- 使用漏洞识别功能与理解程度呈负相关（p = 0.01，效应量 −0.35）。
- 96 份报告里有 20 份存在误解，LLM 组与非 LLM 组各占一半，即误解并不只是 LLM 带来的。

### 高分者怎么用 LLM
- 表现最好的参与者平均每个函数查询 1.71 次，最差的为 3.43 次；对超过 40 行的函数，分别为 4.73 次和 9.69 次。
- 前 10 名中有 9 人采用“第一次访问某函数就查询”的策略，其理解率为 0.13，总体为 0.08（p = 0.01）。
- 最常见的有用组合是“函数总结后重命名”，共出现 154 次；专家的自评高估了部分功能的实用性。

### 作者的讨论
LLM 最擅长“可压缩”的认知工作，即总结边界清晰的函数、识别标准算法，帮助的是第一轮理解，而不是深入的迭代分析；幻觉漏洞报告可能带偏分析。

## 贡献与意义

- 把“LLM 逆向能力”的讨论从模型准确率拉回到人机协作，给出带对照的定量证据（调查加受控实验）。
- 与 [09 ReSym](09-resym-ccs24.md) 互补：ReSym 研究自动化恢复的技术，本文研究这类辅助交到人手里之后的真实效果，尤其是产物数量增加并不等于理解增加。
- 与同样是人因研究的 [41 LLMs in the SOC](41-llms-in-the-soc-sp26.md) 呼应：两者都表明 LLM 更多是帮人理解和建立上下文，而不是替人下结论；本文进一步用对照实验量化了这一点。
- 获 NDSS 2026 Best Paper Award。

## 局限

作者自述的局限：
- 只做静态分析，没有调试器等动态工具。
- 题目规模小、未混淆，复杂数学运算有限。
- 经验水平为自评。
- 提示词由研究团队编写，可能影响结果。

读原文时需要注意的不一致（本文发现，不是作者的结论）：
- 加速幅度在摘要中写作 2.4 倍，引言中写作 238%，与正文的 248% 不一致，本文引用正文数字，具体以原文为准。
- 评分标准的检查点数与最高分在原文中对不上。
- 个别被标为显著的 p 值（p = 0.4）并不显著。
- 调查中的受访者以学生为主，样本不一定代表工业界逆向工程师。
- 受试 LLM 为 2024 年前后的模型（GPT-4o 等），新模型下结论可能不同。

## 对研究者的启示

- 评估逆向类 LLM 工具不能只看产物的准确率或数量，要测人的理解程度。
- 工具设计上，对漏洞识别这类易产生幻觉的功能要谨慎，或者给出可验证的依据。
- 在用户研究中报告分经验层级的结果：同一个工具对新手和专家的效果可以完全不同。
- 若要复现，需要先核对原文中上述不一致的数字。
